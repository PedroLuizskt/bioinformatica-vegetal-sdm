1.1 Objetivos da aula

Ao final desta aula o ambiente deve:

  • rodar Python e R isolados do sistema, com versões travadas em arquivo;
  • impor, por código e não por disciplina, um teto de threads (4) e de memória;
  • permitir que R e Python coexistam no mesmo documento Quarto;
  • passar nos testes de fumaça scripts/smoke_test.py e scripts/smoke_test.R.

1.2 Fundamentação: por que o ambiente é parte do método

Um resultado de SDM ou uma filogenia é função dos dados, do algoritmo e das versões do software. Uma mudança de versão do maxnet, do terra ou do alinhador pode alterar previsões e topologias sem nenhum erro visível. Por isso o ambiente é tratado como artefato científico, em três camadas:

Camada Python R O que garante
Isolamento .venv biblioteca do projeto (renv/library) o projeto não depende do que está instalado no sistema
Intenção requirements/base.txt lista em R/01_instalar_pacotes.R quais pacotes e versões mínimas o projeto exige
Trava requirements.lock.txt renv.lock a versão exata de cada pacote, inclusive dependências

O renv mantém um cache global e liga cada biblioteca de projeto a ele; por isso dezenas de projetos R custam pouco disco. O venv não tem esse mecanismo: cada ambiente Python ocupa algumas centenas de MB.

1.3 Fundamentação: o modelo de memória que vamos respeitar

A máquina tem 7,73 GB utilizáveis, dos quais o Windows, o VS Code e o navegador consomem de 2,5 a 3,5 GB. Sobram de 4 a 5 GB por processo de análise. Três fatos técnicos determinam as regras de engenharia da trilha.

1. Raster global não cabe em memória. Uma camada WorldClim de 30 segundos de arco tem 43.200 × 21.600 células. Em float32:

celulas <- 43200 * 21600
gb_por_camada <- celulas * 4 / 1024^3
c(gb_por_camada = round(gb_por_camada, 2),
  gb_19_bioclim = round(19 * gb_por_camada, 1))
gb_por_camada gb_19_bioclim 
         3.48         66.00

As 19 variáveis bioclimáticas globais somariam mais de 60 GB. O terra resolve isso lendo em blocos do disco e gravando resultados intermediários em arquivos temporários; nosso papel é recortar para a área de estudo antes de extrair tabelas e limitar a fração de RAM que ele pode usar.

2. No Windows, paralelismo multiplica memória. Não existe fork. Um cluster PSOCK do R ou um multiprocessing com spawn no Python sobe processos novos que reimportam pacotes e recebem cópias dos dados. Quatro workers com 1 GB de dados cada são 4 GB além da sessão principal.

3. Bibliotecas numéricas criam threads por conta própria. O BLAS do NumPy e o OpenMP usam, por padrão, todos os 12 threads lógicos do i5-1235U. Isso disputa CPU com o próprio paralelismo explícito e aumenta a memória de trabalho.

1.4 Como as regras viraram código

Regra Mecanismo Onde está
Teto de 4 threads variáveis OMP_NUM_THREADS, OPENBLAS_NUM_THREADS, MKL_NUM_THREADS .env, .Renviron e bioflora.recursos.aplicar_limites_threads()

Editor leve Pylance sem indexação global; pastas de dados fora do file watcher .vscode/settings.json
NotaPor que dois ganchos para o terra

O terra recria suas opções internas no .onAttach, que o R executa depois dos ganchos de onLoad. Um gancho só em onLoad é silenciosamente desfeito por library(terra). Registrar a mesma função também no evento attach reaplica os limites depois do .onAttach; o onLoad continua cobrindo o uso apenas com terra::funcao(). Esse comportamento foi verificado empiricamente no teste de fumaça, que confere memmax e tempdir depois de carregar o pacote.

ImportanteOrdem de importação no Python

import bioflora deve vir antes de import numpy em scripts pesados. O BLAS lê as variáveis de threads no momento em que é carregado; depois disso, mudar os.environ não tem efeito.
